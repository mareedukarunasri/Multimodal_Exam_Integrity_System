# API Documentation

## Multimodal AI-Based Exam Cheating Behaviour Analysis System

The backend of the system is implemented using FastAPI. The APIs provide communication between the examination frontend, monitoring modules, database, risk analysis system, and machine learning module.

---

## Base URL

```text
http://127.0.0.1:8000
```

---

## 1. Health Check

### Endpoint

```text
GET /health
```

### Purpose

Checks whether the backend server is running correctly.

### Example Response

```json
{
    "status": "ok"
}
```

---

## 2. Start Exam Session

### Endpoint

```text
POST /api/exam/start
```

### Purpose

Creates a new examination session for the student.

The session receives a unique session ID. Monitoring events generated during the examination are associated with this session.

### Example Request

```json
{
    "student_id": "S001"
}
```

### Example Response

```json
{
    "session_id": "<generated-session-id>",
    "student_id": "S001"
}
```

---

## 3. End Exam Session

### Endpoint

```text
POST /api/exam/end
```

### Purpose

Ends the currently active examination session.

### Example Request

```json
{
    "session_id": "<exam-session-id>"
}
```

### Purpose of Session Ending

* Records the examination end time.
* Changes the session status.
* Prevents new monitoring events from being associated with the completed session.

---

## 4. Browser Event API

### Endpoint

```text
POST /api/browser-events
```

### Purpose

Receives browser monitoring events from the frontend.

### Example Request

```json
{
    "student_id": "S001",
    "event_type": "tab_hidden",
    "event_time": "2026-09-14T10:20:00Z",
    "session_id": "<exam-session-id>"
}
```

### Supported Browser Events

```text
copy
paste
cut
right_click
tab_hidden
tab_visible
window_blur
window_focus
fullscreen_exit
```

### Processing Flow

```text
Browser Event
      |
      v
FastAPI
      |
      v
Risk Score
      |
      v
SQLite Database
```

## 6. Student Risk API

### Endpoint

```text
GET /api/student-risk
```

### Purpose

Returns the risk summary for the selected examination session.

### Query Parameter

```text
session_id
```

### Example

```text
GET /api/student-risk?session_id=<exam-session-id>
```

### Information Returned

The API can provide information such as:

* Student ID
* Session ID
* Total events
* High-risk events
* Medium-risk events
* Low-risk events
* Browser risk
* Camera risk
* Behaviour risk
* ML risk
* Final risk
* Final risk level

### Example Response

```json
{
    "student_id": "S001",
    "session_id": "<exam-session-id>",
    "total_events": 39,
    "browser_risk": 38,
    "camera_risk": 40,
    "behaviour_risk": 38,
    "ml_risk": 0,
    "final_risk": 40,
    "risk_level": "MEDIUM"
}
```

## 7. ML Prediction API

### Endpoint

```text
GET /api/ml-prediction
```

### Purpose

Runs the machine learning model for the selected examination session.

### Query Parameter

```text
session_id
```

### Example

```text
GET /api/ml-prediction?session_id=<exam-session-id>
```

### Machine Learning Algorithm

The system currently uses:

```text
Random Forest Classifier
```

### Input Features

```text
tab_hidden
window_blur
copy
paste
cut
fullscreen_exit
total_events
```

### Example Output

```json
{
    "prediction": "CHEATING / SUSPICIOUS",
    "session_id": "<exam-session-id>",
    "total_events": 39,
    "tab_hidden": 2,
    "window_blur": 4,
    "copy": 1,
    "paste": 1,
    "cut": 1,
    "fullscreen_exit": 0
}
```

## 9. Error Handling

The backend validates incoming requests and returns appropriate HTTP responses when invalid or incomplete data is received.

Typical problems include:

* Missing session ID
* Invalid student ID
* Invalid event data
* Backend unavailable
* Invalid examination session

The frontend logs API failures in the browser console for debugging.
